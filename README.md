## 3. Листинги модулей с комментариями

### Модуль 1: `chapter1.bat` (Моделирование процесса выбора технологий)
Скрипт задаёт пользователю серию вопросов о требованиях организации (централизованное управление, нагрузка на рабочие станции, сертификация ФСТЭК/ФСБ), начисляет баллы кандидатам с помощью `set /a` и `choice`, после чего формирует итоговую рекомендацию.

```bat
@echo off
chcp 65001 >nul
set score_kaspersky=0
set score_eset=0
set score_drweb=0

echo === Модуль выбора антивирусного решения ===
echo Контекст: офис на 50 рабочих станций, централизованное управление.
echo.

echo Вопрос 1: Насколько критично наличие единой консоли централизованного управления и детальных политик безопасности?
echo 1. Максимально критично (нужен полный контроль над 50 ПК, аудит устройств и веб-контроль)
echo 2. Важно (базовое удалённое развёртывание и мониторинг обновлений)
echo 3. Не критично (подойдёт простая настройка групп станций)
choice /c 123 /n
if errorlevel==3 set /a score_drweb+=10
if errorlevel==2 set /a score_eset+=15
if errorlevel==1 set /a score_kaspersky+=20

echo.
echo Вопрос 2: Какая аппаратная нагрузка на рабочие станции допустима?
echo 1. Минимальная (много слабых офисных ПК, нужна лёгкость агента)
echo 2. Средняя (современные офисные компьютеры)
echo 3. Не имеет значения (главное — глубина эвристического анализа)
choice /c 123 /n
if errorlevel==3 set /a score_kaspersky+=15
if errorlevel==2 set /a score_drweb+=10
if errorlevel==1 set /a score_eset+=20

echo.
echo Вопрос 3: Требуется ли сертификация ФСТЭК/ФСБ и отечественная техподдержка для корпоративного сектора?
echo 1. Да, обязательны отечественная разработка и сертифицированные сборки
echo 2. Желательна локальная поддержка и простое лицензирование
echo 3. Нет жёстких регуляторных требований
choice /c 123 /n
if errorlevel==3 set /a score_eset+=15
if errorlevel==2 set /a score_drweb+=15
if errorlevel==1 set /a score_kaspersky+=15
if errorlevel==1 set /a score_drweb+=15

echo.
set "rec_tech=Kaspersky Endpoint Security"
set "max_score=%score_kaspersky%"
if %score_eset% gtr %max_score% (
    set "rec_tech=ESET NOD32"
    set "max_score=%score_eset%"
)
if %score_drweb% gtr %max_score% (
    set "rec_tech=Dr.Web"
    set "max_score=%score_drweb%"
)

echo Баллы кандидатов: Kaspersky=%score_kaspersky%, ESET NOD32=%score_eset%, Dr.Web=%score_drweb%
echo Рекомендация: %rec_tech%
echo %rec_tech%>last_tech.txt
pause
```

### Модуль 2: `chapter2.bat` (Формализация процесса ревьюирования)
Модуль демонстрирует 3 фрагмента кода, связанных с антивирусным ПО (проверка лимита 50 станций, анализ карантинного файла, отправка политик на сервер). Пользователь определяет тип дефекта, получает/теряет очки, а в конце система вычисляет процент точности и присваивает уровень (`Junior`, `Middle`, `Senior`).

```bat
@echo off
chcp 65001 >nul
set score=0
set correct=0
set total=3

echo === Модуль формализации процесса ревьюирования ===
echo Предметная область: скрипты и конфигурация антивирусной защиты (Вариант 8)
echo.

echo Фрагмент 1 (проверка количества лицензий на рабочие станции):
echo 10: def check_workstation_limit(active_agents):
echo 11:     if active_agents ^> 50:
echo 12:         return "Limit exceeded"
echo 13:     return "OK"
echo.
echo Какой дефект здесь скрыт?
echo 1. Магическое число (50)
echo 2. Утечка ресурса
echo 3. Неинициализированная переменная
choice /c 123 /n
if errorlevel==3 (
    echo Неверно (-5 очков). Правильный ответ: 1 (число 50 нужно вынести в константу MAX_STATIONS).
    set /a score-=5
) else if errorlevel==2 (
    echo Неверно (-5 очков). Правильный ответ: 1 (число 50 нужно вынести в константу MAX_STATIONS).
    set /a score-=5
) else if errorlevel==1 (
    echo Верно (+10 очков)! Лимит рабочих станций (50) должен быть вынесен в именованную константу.
    set /a score+=10
    set /a correct+=1
)
...
```

### Модуль 3: `chapter3.bat` (Сравнительный анализ альтернатив методом WSM)
Модуль запрашивает веса трёх критериев (проверяя, что их сумма равна 100), принимает экспертные оценки (1–5) для *Kaspersky Endpoint Security*, *ESET NOD32* и *Dr.Web*, вычисляет взвешенные суммы $S = \sum (W \times X)$, выводит таблицу и определяет победителя.

```bat
@echo off
chcp 65001 >nul
echo === Модуль сравнительного анализа антивирусных решений (WSM) ===
...
set /a total_weight=w1+w2+w3
if %total_weight% neq 100 (
    echo Ошибка: сумма весов равна %total_weight%, а должна быть равна 100!
    pause
    exit /b 1
)
...
set /a score_k=k_1*w1+k_2*w2+k_3*w3
set /a score_e=e_1*w1+e_2*w2+e_3*w3
set /a score_d=d_1*w1+d_2*w2+d_3*w3
```

### Главный интеграционный файл: `lab_system.bat`
Объединяет все три модуля в единое консольное меню. При выборе пункта `4` последовательно вызывает `chapter1.bat`, `chapter2.bat` и `chapter3.bat` через команду `call`, собирает результаты и записывает их в `report.txt`.

```bat
@echo off
chcp 65001 >nul

:menu
cls
echo ====================================================
echo   СИСТЕМА МОДЕЛИРОВАНИЯ ПРОЦЕССОВ РАЗРАБОТКИ ПО
echo   Вариант 8: Выбор антивирусного решения (50 ПК)
echo ====================================================
echo.
echo 1. Модуль выбора технологий
echo 2. Модуль инспекции кода
echo 3. Модуль сравнительного анализа
echo 4. Запустить все модули последовательно
echo 5. Выход
echo.
set /p choice="Ваш выбор: "
...
```

## 7. Описание результатов работы интегрированной системы
* **Диалоги и вопросы в модулях:**
  * В **Модуле 1** система уточняла критичность единой консоли управления для 50 рабочих станций, допустимую нагрузку на ПК и требования по сертификации ФСТЭК/ФСБ.
  * В **Модуле 2** проверялись навыки поиска дефектов в Python-коде: магического числа `50`, утечки файлового дескриптора при раннем `return` и отсутствия блока `try/except` при синхронизации политик.
  * В **Модуле 3** задавались веса критериев («Централизованное управление», «Уровень защиты и детекта», «Низкая нагрузка и стоимость») с проверкой суммы `100` и оценки по шкале `1–5`.
* **Сформированные рекомендации:**
  * По профилю проекта (Модуль 1) и по методу взвешенной суммы WSM (Модуль 3) оптимальным решением для офиса на 50 ПК с централизованным управлением стал **Kaspersky Endpoint Security**.
  * В Модуле 2 при правильном определении всех 3 дефектов точность составила **100%**, присвоен уровень **Senior**.
* **Итоговый отчёт системы (`report.txt`):**
  * После завершения пункта `4` система вывела сводку по всем трём модулям в консоль и автоматически сохранила её в файл `report.txt`.
* **Впечатления от работы с системой:**
  * Использование `.bat`-сценариев позволило быстро формализовать инженерные решения без сторонних зависимостей, а модульная архитектура с вызовом через `call` упростила отладку каждого этапа отдельно.

## 8. Инструкция по запуску системы для другого пользователя
1. Скачайте репозиторий (нажмите **Code → Download ZIP** на странице GitHub и распакуйте архив в любую папку на ПК под управлением Windows) или клонируйте его командой:
   ```bash
   git clone https://github.com/<ваш_логин>/<название_репозитория>.git
   ```
2. Убедитесь, что все файлы (`lab_system.bat`, `chapter1.bat`, `chapter2.bat`, `chapter3.bat`) находятся в **одной папке**.
3. Запустите главный файл **`lab_system.bat`** двойным щелчком левой кнопки мыши.
4. Выберите нужный модуль (`1`–`3`) или пункт **`4`** для полного последовательного прохождения всех этапов и генерации файла отчёта `report.txt`.
