# Итоговый аналитический отчет (Лабораторная работа №1)

## 1. Резюме (Executive Summary)
В рамках выполнения лабораторной работы был спроектирован процесс разработки для нового микросервиса «Расчет корзины и скидок». Выполнен выбор СУБД на основе взвешенного анализа, настроена инфраструктура проекта с использованием модели Git Flow, внедрен автоматический контроль качества кода (CI/CD Quality Gates), проведен реверс-инжиниринг legacy-алгоритма и составлен план код-ревью.

## 2. Сравнительный анализ технологий
### 2.1. Матрица принятия решений
| Критерий | Вес | PostgreSQL | MongoDB | PostgreSQL (взвешенно) | MongoDB (взвешенно) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| Поддержка ACID-транзакций | 0.35 | 5 | 3 | 0.35 * 5 = 1.75 | 0.35 * 3 = 1.05 |
| Производительность чтения/записи | 0.25 | 4 | 5 | 0.25 * 4 = 1.00 | 0.25 * 5 = 1.25 |
| Гибкость схемы данных | 0.15 | 3 | 5 | 0.15 * 3 = 0.45 | 0.15 * 5 = 0.75 |
| Экосистема и средства аудита | 0.15 | 5 | 4 | 0.15 * 5 = 0.75 | 0.15 * 4 = 0.60 |
| Стоимость владения и поддержки | 0.10 | 4 | 3 | 0.10 * 4 = 0.40 | 0.10 * 3 = 0.30 |
| **ИТОГО:** | **1.0** | — | — | **4.35** | **3.95** |

### 2.2. Расчет и обоснование выбора
* **Формула расчета:** $\text{Оценка} = \sum (\text{Вес} \times \text{Балл})$
* **PostgreSQL:** $4.35$
* **MongoDB:** $3.95$
* **Обоснование:** Победителем выбрана **PostgreSQL** из-за жестких требований к поддержке ACID-транзакций при работе с финансами и системой лояльности.

## 3. Архитектура и контроль версий
### 3.1. Настройка репозитория
* Использована модель ветвления Git Flow (`main`, `develop`, `feature/*`).
* Настроены файлы `.editorconfig` и `.github/CODEOWNERS`.

### 3.2. Контроль доступа
* Настроено правило защиты ветки `develop` (Require a pull request before merging).

## 4. Инструментальный контроль качества
### 4.1. Настройка CI/CD
* Настроен файл `.github/workflows/qa.yml` для автоматического запуска линтера `flake8` с ограничением длины строки 80 символов.

### 4.2. Работа Quality Gate
* Проведено тестирование методом «сломать и починить»: при внесении умышленной ошибки линтер выдал красный статус, после исправления статус сменился на зеленый.
